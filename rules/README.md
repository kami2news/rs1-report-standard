RS1（Research report Standard 1）は研究レポートの標準。正本は GitHub の `kami2news/rs1-report-standard`（https://github.com/kami2news/rs1-report-standard）で、このデザインシステムは画面で見るための写し。レポートの「型」を一つにそろえ、報告の種類（実験・文献調査・フィールド観測・データ解析・ゼミのレジュメ・卒業研究・論述・小レポート）に応じて章立てだけを差し替える。ルールは各大学の図書館・学習支援センターが公開しているレポート・論文の手引きを参考にした（`patterns/99-sources.md`）。部品・色・書体は共通で、種類ごとの違いは `patterns/` の各ページにある。
*One skeleton for every research report; only the chapter plan changes by report type (see `patterns/`).*

## 使い方（最初に読む）

1. 何を報告するかを `patterns/00-chooser.md` で選ぶ。迷ったら、主な成果が何かで決める（測定値か、文献の整理か、現地データか、計算結果か、途中経過か、研究全体か、自分の意見の論証か、毎回の短い課題か）。
2. 選んだパターンのページ（`patterns/01-…` から `08-…`）の章立てと骨子（コピー用）を使う。足りない章は別パターンから借りてよい（`00-chooser.md` の「混成ルール」）。
3. 部品は `components/` の 13 種を使う。ページ幅・余白は `page-width`・`page-height`・`page-margin`（A4 縦）。
4. 提出前に、選んだパターンのチェックリストと、下の「共通ルール」を確認する。

## 授業の指定との関係（実情に合わせる）

授業や学科の指定は、このフォーマットより常に優先する。RS1 は、指定がない部分を埋めるための標準。よくある指定と、そのときの合わせ方は次のとおり。

| よくある指定 | 合わせ方 |
| --- | --- |
| A4・1 行 40 字×30 行（または 35・40 行）・10.5 pt | Word の「ページ設定」で文字数と行数を指定する（`typeset/11-docx.md` の 6 節）。この場合、行送りの規定（固定値 19.5 pt）は使わない |
| 書体は明朝（MS 明朝・游明朝）／余白は上 30〜35 mm | 指定どおりにする。`typeset/00-environment.md` の書体の規定より優先。PDF で出せば相手の環境に左右されない |
| 表紙を付ける／付けない | 付けるときは `CoverPage` か実験の表紙、付けないときは `TitleBlock` の簡易ヘッダー |
| 文末に総文字数を書く | 本文の字数を Word の「文字カウント」で数え、最後の行に「（総文字数：○○字）」 |
| Word ファイル（.docx）で提出 | 教員がコメントを入れるため。PDF にせず、変更履歴とコメントを消して .docx のまま出す |
| ファイル名を「学籍番号_氏名」で | 日本語の氏名を含めてよい。提出に使う PC の上で付ける |
| 手書き（レポート用紙・原稿用紙） | ボールペンで書く。構成・図表の決まりは同じ |
| 学内システム（LMS）の入力欄に直接書く | 見出しと図表は使えないので、段落と改行だけで組む（パターン H の書き方） |

字数指定は ±10% 以内に収める。表題・氏名・参考文献は、ふつう字数に含めない（指示があれば従う）。

## 共通ルール（全パターン共通）

**レポートは感想文ではない。** 「主張」と、それを支える「根拠」を書く。根拠は、自分のデータか、出典を示した文献にする。
**構成の骨格。** 表題 → 本文（問い → 方法 → 結果 → 考察 → 結論）→ 参考文献 → 付録。パターンごとに章の名前と必須・任意が変わるが、順序は変えない。論述型（G）は序論・本論・結論の 3 部構成で、分量は序論 10%、本論 70〜80%、結論 10〜20% を目安にする。
**要旨は研究の文書だけ。** 授業のレポート（A〜D、G、H）には要旨を付けない。付けるのは卒業論文（F）と、授業・学会で指示されたときだけ。ゼミの進捗報告（E1）は要旨の代わりに冒頭へ 3 行の要約を置く。
**事実と解釈を分ける。** 結果の章には測定・観察・計算の事実だけを書き、推測・判断・意見を混ぜない。理由づけや評価は考察に書く。
**書く順番。** アウトライン（章立てと各章の要点の箇条書き）を先に作り、方法 → 結果 → 考察 → 序論 → 結論の順に書く。要旨を付けるときは、最後に書く。
**自分の言葉で書く。** 目的や原理を、実習書・教科書から丸写ししない。理解した内容を要約して書く。
**課題の指示が最優先。** 授業・研究室・学科に書式や構成の指示があるときは、それに従う。このフォーマットは、指示のない部分を埋めるために使う。
**見出しは 3 階層まで。** 章 `t-h1`、節 `t-h2`、項 `t-h3`。番号は 1 / 1.1 / 1.1.1。参考文献・付録・謝辞は番号を付けない（`rp-unnumbered`）。
**文体。** 日本語は「だ・である」調に統一し、「です・ます」と混ぜない。方法と結果は、実際にやったこととして過去形で書く（「〜した」）。主語を省くときも、自分の結果か先行研究かが分かるように書く。「思う」「感じた」は使わず、「考えられる」「示唆される」と根拠を添える。要旨とキャプションには英語を併記してよい（任意）。日本語を主、英語を従とする。
**数値と単位。** SI 単位を基本にし、数値と単位の間に半角スペースを入れる（例：12.3 mg/L）。有効数字は測定精度に合わせ、不確かさは ± で示す。
**図表。** 図の説明は図の下、表の説明は表の上に置く。すべて本文で番号を引いて言及する。キャプションだけで「何を・どこで・いつ・単位」が分かるようにする。表は三線表（縦罫なし）。軸ラベルに単位を入れ、系列は色だけでなくマーカーと線種でも区別する。
**引用。** 番号方式 `[1]`（本文に出てくる順）。参考文献は「著者（年）題名，誌名，巻（号），頁，DOI」の順。孫引きは避け、原典を見られなければその旨を書く。引用は 4 つの条件を守る：自分の文と引用部分をはっきり分ける（「」で囲む）、必要最小限にする、自分の文が主で引用が従（量も自分の文が多い）、出典を必ず書く。出典を書かずに他人の文や図を使うと剽窃になる。Web ページは更新されるので、閲覧日も書く。文献値（物性値・定数）も出典を付ける。 著者は 5 名までは全員、6 名以上は最初の 3 名と「ほか」（欧文は「et al.」）。頁の無い電子ジャーナルは頁の位置に論文番号を書く。CC ライセンスの図を転載するときは、出典・変えた点・ライセンス名を図のキャプションに書き、参考文献には文献だけを書く。細かい書き方は `References` と `FigureTable` の説明。
**情報源の質。** 出典と書き手がはっきりした情報を根拠にする。発信者の分からない Web 記事やまとめサイトは、概要をつかむのに使ってよいが、根拠にはしない。
**再現性。** 日時・場所・機器・ソフトのバージョン・パラメータを書く。コードやデータは付録か、参照先を示す。
**支援ツールの利用。** 生成 AI やコード生成を使った場合は、授業・研究室の規定に従って使った範囲を付記する。
**体裁。** 全頁に頁番号を付ける。PDF で提出するときは、ファイル名に学籍番号・氏名・課題名を入れる（指示があればそれに従う）。

## 提出前の共通チェック

- [ ] 課題・授業の指示（字数・頁数・書式・締切・提出方法）を守っている
- [ ] 表紙に、講義名・課題名・学籍番号・氏名・提出日がある
- [ ] 問い（目的）と結論が、同じ言葉で対応している
- [ ] 結果に解釈を混ぜていない／考察が結果の図表を引いている
- [ ] 文体（だ・である）がそろい、口語・感想表現がない
- [ ] 図表・式に番号があり、すべて本文で引かれている
- [ ] 本文の `[n]` と参考文献の一覧が一対一で対応している
- [ ] 引用部分と自分の文が区別でき、出典がすべてある
- [ ] 頁番号がある。誤字脱字を声に出して読んで確かめた

## 色と書体

- 本文は `t-body`、見出しは `t-h1`〜`t-h3`、表題は `t-title`、図表の説明と表の中身は `t-caption`、脚注とヘッダー・フッターは `t-note`、ラベル類は `t-meta`、コードは `t-code`。
- 文書の中の色は、文字の `ink` と、補助の文字・細い線の `ink-muted`・`line-strong` だけ。色を使うのはグラフの系列（`chart-1`〜`chart-4`）だけで、見出し・ラベル・リンク・強調に色を付けない。強調は太字か語順で。
- 囲み・背景色・角丸・影を文書の中で使わない。区切りが要るときは細い線 1 本（表題の下、コードの上下、脚注の上、三線表）。要旨・注記は字下げとラベルの語で示す。
- `brand`（`#10218B`）・`brand-tint`・`info`・`warning` は、画面の操作部品（パターン切り替えのタブ）とデザインシステムの表紙だけで使う。
- 注記の種類はラベルの語（注記・前提・注意・未解決）で区別する。
- `danger` は校正用。提出版には残さない。
- 書体は Noto Sans JP（400・700）とコード用の Noto Sans Mono（400）だけ。OS の標準書体（游ゴシック・ヒラギノ・メイリオ）は使わない。LaTeX では同じデザインの原ノ味角ゴシックを使う。OS ごとの違いを避ける決まりは `typeset/00-environment.md`。
- 日本語の字形を正しく選ぶため、文書の `<html>` に `lang="ja"` を付ける。
- ダークテーマは画面で読むときだけ。印刷・PDF はライトテーマで出力する。

## グラフの色

系列は `chart-1`〜`chart-4` の順に使い、色・マーカー・線種を必ず組にする。1 = ● 実線、2 = ■ 破線、3 = ▲ 点線、4 = ◆ 一点鎖線（参照線・理論値）。`chart-2`〜`chart-4` は明るさが近く、白黒印刷では色で見分けられないので、マーカーと線種で区別できることが前提。系列が 5 つを超えるときは、図を分けるか表にする。グラフの地は `surface`、軸は `line-strong`、目盛り線は `line`、軸ラベルと目盛りの数字は `t-note`。

## 出力形式（LaTeX・Word・PDF）

文書は LaTeX か Word で作り、PDF で提出する。形式ごとの規定は `typeset/` にある：`00-environment.md`（OS の違いを避ける決まり：書体・文字・ファイル名・画像）、`10-latex.md`（LuaLaTeX ＋ jlreq）、`11-docx.md`（Word のスタイル）、`12-pdf.md`（PDF/A-2b・ファイル名・提出前チェック）。LaTeX テンプレートの全文は `typeset/13-latex-source.md`、出力見本は `templates/rs1-report-sample.pdf`。テンプレートのファイル一式（`rs1.sty`・`rs1-report.tex`・`refs.bib`・実験レポート用の `rs1-report.docx`・小レポートと論述用で 40 字×30 行に設定済みの `rs1-short.docx`）は rs1-templates.zip として別に配布する。どの形式でも、版面・文字サイズ・図表の決まりは RS1 のトークンと同じ値にそろえてある。

## 印刷・PDF

- 用紙は A4 縦、余白 25 mm（`page-margin`）。`bundle.css` の印刷用ルールが、台・影・画面用のヘッダーとフッターを外す。頁番号は Word・LaTeX・ブラウザの印刷設定で付ける。
- 文字の大きさの換算（96 dpi）：`t-title` 18pt、`t-h1` 15pt、`t-h2` 12pt、`t-body`・`t-h3` 10.5pt、`t-caption`・`t-code` 9pt、`t-note` 8pt。Word で作るときはこの pt を使う。
- 図表・式・注記枠・コードは頁をまたがない。見出しだけが頁末に残らない（`break-inside: avoid`／`break-after: avoid`）。
- 提出前に白黒で印刷プレビューし、図の系列と注記枠の種類が見分けられるかを確かめる。

## 部品の使い分け

| 部品 | 使う場面 |
| --- | --- |
| `ReportPage` | A4 縦のページ枠。ランニングヘッダー（文書名）とフッター（頁番号）を付ける |
| `CoverPage` | 卒業研究・論文（F）の表紙。学科の様式がないときだけ |
| `TitleBlock` | 表紙を付けない文書の頭。標準は右上に講義名・提出日・氏名、中央に表題、その下に条件（実験日・天候など）を 1〜2 行、簡易ヘッダー（`rp-titleblock--compact`）は科目名・学籍番号・氏名を 1 行（G・H・E） |
| `TableOfContents` | 目次。F で必須、C で任意 |
| `Abstract` | 要旨とキーワード。卒業論文と、指示があるときだけ。中間報告では「要約 3 行」 |
| `SectionHeading` | 章・節・項の見出し。番号は自動 |
| `FigureTable` | 図・表とキャプション。三線表 |
| `Equation` | 式と式番号。式のあとに記号の説明（where 文）を付ける |
| `CodeBlock` | 付録・方法のコードとコマンド。言語と版を説明に書く |
| `Callout` | ［注記］［前提］［注意］［未解決］のラベルと字下げ。本文の流れを止めてよい情報だけに使う |
| `Footnote` | 読まれなくても論旨が通る補足。出典には使わない |
| `References` | 参考文献の一覧（番号方式） |
| `PatternSelector` | 報告の種類ごとの章立てを切り替えて確かめる |

## 守ること

- 余白と間隔は `space-1`〜`space-8` の 4px 刻みだけを使う。
- 角丸（`radius-*`）と影（`page-shadow`）は画面の部品と、画面で見るときのページの台だけ。ページの中の要素には付けない。
- 色名やコード値を直接書かず、トークン名で指定する。
- 校正時に残す未解決事項は `Callout` の「未解決」で示し、提出前に解消する。
